# Псевдоклассы и селекторы CSS

> **Enforce:** [`.cursor/rules/css-selector-pseudo-classes.RULE.md`](../../../.cursor/rules/css-selector-pseudo-classes.RULE.md).

- **По умолчанию:** обычные списки селекторов (`h1`, `a`, `.link-plain`).
- **Не использовать** **`:where()`**, **`:is()`**, **`:not()`**, **`:has()`** «для удобства», чтобы вырезать UI из глобальных правил элементов или имитировать сброс каскада.
- **Семантические классы** (`.btn`, `.article-prose`, BEM-блоки) — основной способ ограничить стили; «голые» элементы — в **`app/css/components.css`** (`@layer base`) — см. [`tailwind-usage-policy.md`](./tailwind-usage-policy.md).

## Почему

- **`:where()`** обнуляет специфичность — может проигрывать Preflight.
- **`:is()`** берёт специфичность самого «тяжёлого» аргумента — легко ошибиться при ревью.
- **`:not()`** прячет связь в глобальном селекторе (`a:not(.btn)`). Лучше **перебить цвет на компоненте** (включая `:hover`), оставив голый `a` простым.
- **`:has()`** связывает предка со структурой потомков — хрупко при смене разметки.

## Исключения

Только если: цель каскада задокументирована комментарием, поведение проверено в скомпилированном CSS, и обычный селектор/класс не могут решить задачу без дублирования.

Если цель — «глобальный `a` / `button` не ломает кнопки», задайте цвет (и **hover** / **dark:**) на **`.btn` / `.btn-*`**, а не `:not(.btn)` и не `:where(button)`.

**Исключение:** селекторы Tailwind **`@custom-variant`** / плагинов, где нужен `:is()` (например `dark` в `theme.css`) — не ручная стилизация элементов.

## Проверка

- [ ] `rg ':where\\(|:is\\(|:not\\(|:has\\(' app/css` — нет совпадений, либо исключение (комментарий / `@custom-variant`).
- [ ] `a.btn` получает цвет из **`.btn-*`**, а не из исключения в правиле `a`.
